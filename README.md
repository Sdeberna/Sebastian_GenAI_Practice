# Inline Email Assistant

A small Wizard-of-Oz class prototype that helps users review and edit prepared email replies through an inline assistant, without opening a separate AI chat.

## First working slice

Read a sample email asking about Thursday at 2 PM. Type an instruction, click **Write with AI** inside the text field, and review a prepared suggestion:

- **Accept:** insert the current suggestion, including manual edits, into the editable reply composer. For subsequent suggestions, **Accept & replace draft** explicitly replaces the existing draft.
- **Edit:** modify the suggestion before accepting it.
- **Regenerate:** show alternate prepared wording for the selected scenario. If the suggestion has manual edits, choose **Keep my edits** or **Discard edits & regenerate** first.
- **Cancel:** dismiss the suggestion, restore the original instruction, and leave any accepted draft unchanged.

After accepting, **New AI instruction** starts another round without reloading. The accepted draft remains visible and editable; generating or cancelling a suggestion does not change it. Empty or whitespace-only instructions show a validation message and never advance. Empty edited suggestions cannot be accepted. This prototype does not send email.

## Open and use

**In Replit:** Open the **Inline Email Assistant** preview. If stopped, start its existing web workflow. No credentials or service configuration are required.

1. Try “Decline Thursday and propose Friday after 3 PM” for the scheduling scenario.
2. Try “Make it nicer but not too formal and explain that I have a class” for the friendly class-conflict scenario.
3. Review, edit, regenerate, accept, or cancel. After accepting, edit the draft or choose **New AI instruction** to repeat.

**Outside Replit:** With Node.js 24 and pnpm 10 installed, run from the repository root:

```sh
pnpm install
PORT=5173 BASE_PATH=/ pnpm --filter @workspace/inline-email-assistant run dev
```

Open `http://localhost:5173/`. The prototype needs no API server or database.

## Simulated AI

AI behavior is **simulated/prepared, not generated by a live AI model**. This is a Wizard-of-Oz interaction demonstration implemented with authored text and a simple keyword rule: an instruction containing the English word **class** selects the friendly class-conflict responses; other non-empty instructions select the standard scheduling responses. Each scenario has two alternate replies. No language model or external API is called to create responses, and there is no hidden human operator.

The interface shows a persistent simulation badge and explains this selection rule. It does not claim to understand arbitrary language or rewrite the existing draft intelligently. Review all text before accepting.

## Three known limitations

1. **Only two English scenarios:** the keyword rule does not understand negation, other schedules, or arbitrary tone requests. **Next step:** expand the prepared examples and add an explicit scenario selector; keep simulation labeling.
2. **Session-only drafts:** refreshing clears instructions and edits. **Next step:** add opt-in browser-local draft saving with a clear reset control, without accounts or a database.
3. **Single isolated composer:** it cannot send email, access Gmail, or assist in other applications. Accepting a second suggestion replaces, rather than intelligently revises, the draft. **Next step:** demonstrate a second local text-field example or a side-by-side replacement preview, without external integrations.
